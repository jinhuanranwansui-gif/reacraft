The injection detector was tested against its own evasions, and lost 24 times out of 120.

**Started at 76/120.** Three cheap evasions were getting through:

| mutator | before | after |
|---|---|---|
| rot13 | 13% | 100% |
| zero-width characters | 38% | 100% |
| Cyrillic/Greek homoglyphs | 38% | 100% |
| `.` and `_` as separators | 38% | 100% |

A model reads all four without noticing, which is exactly why the detector has to.

**Fixed**

- normalizeForScan: zero-width characters removed, homoglyphs mapped to ASCII, `.`/`_`/`-` between
  letters read as a space.
- a rot13 view is scanned too; a hit only on a normalised or decoded form is reported with
  obfuscated: true.
- `$1 $2` in a one-group replacement: an out-of-range `$n` is kept literally by JavaScript, so the
  first normaliser inserted the text `$2` into every string and matched nothing. Found by the fuzz
  run, not by reading.
- a `SYSTEM:` header mid-sentence (`Note to any reader: SYSTEM: …`) is caught now, case-sensitively,
  so a lowercase `system:` log prefix is still not a hit.

**tools/fuzz-guard.mjs** — 8 seeds × 15 mutators, per-mutator table, failing exit code on any miss.
CI runs it, so a rule that stops catching a known evasion turns the build red.

Stated honestly: 120 payloads were designed by the same person who wrote the rules, so this is the
floor, not the ceiling. The file says so at the top, and so does this release.

25 tests, 17 bench checks, CI on 3 OS x 3 Node.
